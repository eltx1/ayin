Reviewer notes: AYIN hosts its first-party server-rendered video interface at ayin.stream within the installed mobile app. The binary contains a restricted, versioned native bridge for Google Mobile Ads, consent, Firebase Analytics/Crashlytics and push. Ordinary interface/content updates use the website deployment; new native capabilities require a new binary. Ads and optional telemetry require the documented consent/audience gates. There is no rewarded-currency system, hidden mini-app catalog, or remote native-code installer. The iOS optional native video browser has a separate login from the hosted interface. Explain enabled functionality consistently to reviewers; do not enable undisclosed functions after approval.

Provide a dedicated, nonprivileged reviewer account through the store's secure review-access fields, with populated playable public videos/Clips. Do not put its password in Git or this document. Live inspection found creator/video listings and one public 6.016-second test MP4 that decoded fully with FFmpeg. This does not establish native-player acceptance or complete review access. Production discovery's empty home rows need review before submission.

For Play, classify each category's collection, sharing/service-provider treatment, optionality and deletion behavior against the deployed services. For Apple, determine linked-to-user and tracking answers from actual processing, consent and merged SDK privacy reports. Do not copy a blanket “no data collected” or “no tracking” answer from the absence of an ATT prompt. The current iOS build selects Firebase AnalyticsCore without the Firebase AdSupport product, disables Analytics IDFV collection, and uses nonpersonalized ad settings; if production processing becomes cross-company tracking, an ATT-compliant implementation and revised disclosures are required before enabling it.

The actual simulator app from CI run `39251709370` contained 20 readable privacy manifests: the app and 19 SDK manifests. GoogleMobileAds declares DeviceID as linked and used for tracking, while the app-owned declaration sets tracking false. Reconcile the combined report and actual processing before submission; this manifest comparison does not prove tracking occurred in the disabled/unconfigured build. SDK manifests also declare advertising, coarse-location, performance and other diagnostic/data categories.

## UGC and release evidence

Use the [Android UGC review checkpoint](./ANDROID_UGC_REVIEW_EVIDENCE.md) for the real Play-delivered candidate before considering public submission. Existing maturity labels and the Kids filter do not establish Android-wide enforcement or age verification.

Existing moderation, privacy/export/delete-account and support paths are retained. Account deletion is a real password-verified, session-fenced request, with a 14-day grace period, an additional 24-hour technical recovery window following deactivation, identity anonymization and asynchronous owned-media cleanup. Sessions and mobile notification bindings are removed by the existing lifecycle. Financial, fraud/security, moderation and audit records can be retained where required; backups/cleanup are not represented as instant erasure. The public deletion resource links the same authenticated browser controls and recovery path rather than creating a second deletion backend.

This candidate exposes authenticated video (Watch and the Clips Details sheet), comment and channel reporting using the existing moderation intake/queue; the channel target uses the existing `Report.channelId` relation without a database migration. Exactly one target and bounded reasons/details are accepted. Browser report drafts bind to the verified opening account and clear on identity suspension/invalidation or backgrounding. Writes verify the current account before and after submission and do not automatically resend an unconfirmed write. Community-post reporting remains on its existing path. Account-wide blocking, unblocking, interaction restrictions and notification filtering are retained. Public anonymous catalog pages remain public; blocking is not a promise to erase public content from the internet. Review response staffing, handling of nonconsensual intimate imagery and terms acceptance with the owner; code alone does not establish timely human moderation.

Registered Android/iOS WebViews may use the independently enabled web GPT/HTML5 IMA path alongside native GMA banners/interstitials. Browser consent remains independent of native UMP; disclose the SDK and web-ad provider collection in the final merged privacy review. Native AVPlayer content IMA is not claimed shipped. Confirm the actual enabled capabilities and the share-extension/App Group privacy details against the final signed archive before submitting this draft.

Use actual signed-device screenshots of Home, Clips, Watch, channel and Account/privacy at the required console sizes. The native icon reuses AYIN's existing A/play identity. No marketing screenshot or device delivery evidence is fabricated. A simulator capture can support layout review, but cannot prove ads, APNs delivery, background execution or performance on a physical device.

Submission remains blocked until the configured SDK/device checks, signing/membership checks, playable review content, actual store screenshots, age/audience declarations and final privacy answers are accepted. Start with internal testing/TestFlight; public publication is a separate owner decision.
