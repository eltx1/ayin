## Acceptance boundaries

Each bundle needs inspected source, relevant real behavior, truthful failure states, green owning gates, rendered originals where UI changes, and exact deployment proof when production behavior changes. Test counts and filename inventories alone do not close a phase.

Physical devices, field Core Web Vitals, real provider acceptance, store signing and store approval require their own evidence and authority. They must be recorded as external gates where unavailable, never replaced with simulated success. Source-code work does not authorize payments, new credentials/access, irreversible production data changes or historical financial corrections.
