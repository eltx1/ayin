# AYIN Admin Creator TV write authority

Actual legacy control-plane TV status writes were audited transactionally but trusted pre-handler authority, had no target snapshot version and no explicit step-up requirement. Directory count/items were separate snapshots with unstable ties. This preparatory API slice adds native-safe original-TV reads, deterministic bounded pages and command protection before rebuilding the existing English/prompt client.

Directory count/items use RepeatableRead, updatedAt/id order and stable startsAt/id order for the existing two current/upcoming schedule summaries. Direct original-ID read shares the same explicit safe projection; UUID400/missing404, strict list filters and private/no-store/Pragma are explicit. Existing Operations/Admin scope remains; Finance cannot read the records.

TV commands capture authenticated session identity and reuse existing credential-first/current-account-role-session authority locks, then lock the actual TV row. Held authority rows prevent revocation changes from passing the commit boundary. The same authority check runs again after the final TV lock wait to renew actual database session expiry and five-minute step-up time. Explicit step-up is required before entering the command too. Optional original updatedAt preserves older-caller compatibility; the native client must always send it. Stale409 is effect-free; successful status/version/disabledAt/audit writes remain one transaction with a monotonic timestamp, even when the original version is in the future. The acknowledgment remains the actual smaller id/name/status/disabledAt/updatedAt projection without invented channel/schedule facts.

Eleven prepared actual AppModule/PostgreSQL cases observe real credential/TV lock waits for role removal, actor suspension/authVersion, captured-session revocation, MFA-version changes, target winners, post-wait reauthentication expiry and actual database-clock session expiry. Safe26-row paging/direct recovery/Finance denial/full pre-existing MFA-audit preservation, future monotonic versions/stale and malformed commands, and a real audit-insert trigger failure/complete rollback/one explicit retry are also checked. Prepared tests are not passing evidence; local API types/canonical lint/format and exact full quality/security/inventory/database/browser gates must be recorded before acceptance.

This is the routed AdminControl TV command boundary. The internal CreatorTvService.setAdminEnabled helper is currently referenced only by tests, and other owner scheduling/overrides/live/provider mutation domains remain separate review. Existing bootstrap Origin protection is unchanged. No provider activation, physical-device or whole-Admin/master certification. Native localized TV workspace and original-target uncertainty/step-up/freeze/browser/image checks remain pending.
