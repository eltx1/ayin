# Studio Content: bounded recent-content pagination

Scope: the existing `/studio/content` library and `GET /creator/studio/content`. Saved Upload History, bulk operations, browser-history interception, `studio.ts`, and the video/caption editors are unchanged by this slice. Source starts at PR246 commit `d28642288bf141274cd6e363dddd7e7e12cdb37a`.

## Contract and behavior

- Existing `channel` / `videos` consumers retain the 50-row default and 100-row maximum. The community video selector continues to use that legacy contract. `actorAccountId`, `page` and nullable `nextCursor` are additive fields.
- OWNER/ADMIN/EDITOR authorization still resolves the earliest currently accessible non-removed channel. A cursor cannot grant access: current membership is checked on every request, and the cursor must match the account, channel, normalized query, status, visibility and page size.
- Rows are ordered by `updatedAt DESC, id DESC`. The cursor contains the timestamp and UUID as issued, rather than asking Prisma to look up a mutable anchor. Editing or deleting the anchor does not move that issued boundary. This is a live recent-content list, not a frozen database snapshot: other edits can move videos between pages. The UI explains this and provides First page.
- Filtering happens in the database before the page bound. Studio requests 25 rows. The API fetches one additional row to determine continuation and only passes the returned rows to advanced metadata hydration. There is no count query, fabricated total, cumulative row cache or all-pages fetch.
- The UI renders one page. It retains at most 100 cursor entries, dropping the oldest when advancing, while the absolute page number can keep increasing. This is a rolling Previous window, not a 2,500-video cap. First page remains available; a truthful message explains when older Previous links have left the window.
- Draft search/status/visibility changes leave the applied page alone. Changed applied filters reset to First page; reapplying identical filters reloads the current page.
- Unchanged/discarded editor close reloads the current issued page. Acknowledged save/unpublish/remove returns to the first page with the same applied filters. A subsequent GET failure retains the separate saved-action acknowledgment and never retries the mutation.
- The isolated page client validates bounded responses, exact response/request scope, stable row ordering, duplicate IDs, enum/date/metadata fields and cursor shape. `requestAccountScope` checks the account before and after the read and sends the expected-account header. Search spaces are encoded as `%20` because that shared request validator deliberately rejects `+`. Cancelled/obsolete reads cannot publish a page. Explicit First-page recovery can rebind after an account/channel change; ordinary paging and editor refresh stay pinned to their original actor/channel.

## Index and measurement

The additive `video_studio_content_cursor_idx` index is `(channelId, updatedAt, id)`. Existing status/publication and cross-channel export indexes cannot directly satisfy channel-local recent ordering. The cursor predicate also supplies a redundant timestamp upper bound so PostgreSQL can use a bounded channel/time range while preserving the exact ID tie-break.

`scripts/measure-studio-content-query.mjs` is restricted to a local AYIN test database. It creates 5,000 measured-channel and 50,000 other-channel videos with ten-row timestamp ties, captures the actual Prisma SQL for first/second/deep/filtered reads, and records five EXPLAIN ANALYZE/BUFFERS executions before and after this one index. It temporarily drops the index inside a transaction which is rolled back, and removes its own synthetic rows afterward. Raw reports retain SQL, parameters, plans, timings, source revision, source status, runtime and fixture context. Measurements are laboratory evidence, not production latency or field Core Web Vitals.

## Independent review follow-up

Review of `caa2d38a` found that a literal `*` search was still rejected by the shared account request allowlist before the fetch. `URLSearchParams` escapes other punctuation but leaves `*` raw. The isolated page client now also encodes it as `%2A`, preserving server search semantics without weakening the shared validator. Added source regressions cover `*`, literal `+` and mixed punctuation round trips, and an actual browser case verifies the encoded request produces a truthful empty result. The original 19-case/images evidence above remains scoped to its original source; the later current-caption union run supplies the corrected-source browser gate.
