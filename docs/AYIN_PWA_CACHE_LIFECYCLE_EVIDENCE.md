# AYIN PWA cache and lifecycle evidence

## Reviewed PWA cache/lifecycle safety candidate

Source inspection after the Live review found that `sw.js` v2 precached `/`, cached broad API/public/discovery reads without respecting private/no-store response directives, immediately activated every installed worker, and deleted unrelated origin caches. The update controller reloaded immediately after posting SKIP_WAITING rather than waiting for controller takeover. These are actual cache/lifecycle defects; the historical PWA ledger was not treated as proof of safety.

The focused v3 candidate caches only neutral offline/icons and immutable Next build assets. API reads, arbitrary images, playback and application documents never enter its cache. Network-failed document navigation gets a bilingual neutral offline page; genuine HTTP errors remain intact. Explicit authenticated/no-store/no-cache/query requests bypass static caching; private/no-store/no-cache responses are not persisted. Activation purges only previous AYIN caches, including the legacy read cache. Installation waits for an explicit update decision, and the accepting tab reloads only after controllerchange. Other tabs do not automatically reload. Update copy tells viewers to save their work; EN/AR labels and bounded failed-update/install recovery replace silent failures.

Behavioral tests execute the worker in a VM with mock browser APIs, verifying cache ownership, exact bypasses, server directives, offline fallback, HTTP errors, one network read on a cache hit and explicit activation. Browser acceptance additionally exercises real production worker storage/offline navigation and a deterministic controller-takeover event. Browser and exact-head CI acceptance remain pending. Local 306 Web tests passed after building workspace packages; lint/types/build evidence is recorded only when complete. This is a justified safety correction before the full Phase9 install/device/performance matrix, not completion of Phase9 or phases6–16.
