Master Phase6 remains open. This focused shared manager serves embedded `/studio/tv` and standalone `/channel/tv`; public Creator TV playback, provider provisioning, ads, media URLs and server ownership/eligibility/audit policies remain authoritative.

Actual review found unchecked casts, an unbounded management read, overlapping per-video writes, blank priority becoming zero and an automatic refresh conflating a committed preference with a failed read. The shared manager now uses an allow-listed correlated snapshot, aggregate15s reads and30s explicit writes, actual account/channel verification before writes and after reads, synchronous single-write guards and matching-video/exact-preference acknowledgment validation. Boolean false, explicit zero order and automatic null order remain distinct. Storage keys and provider resource identifiers are omitted from presentation.

Native EN/AR controls and disclosure expose every returned row in twenty-row presentation pages. Existing server management remains an unpaginated owned library; the client rejects malformed/duplicate/over10000 rows instead of silently truncating, so production-scale DB paging/cardinality remains open. Actual eligible public validated MP4 videos and existing configured rotation tie-breaks are retained. No media/provider readiness is inferred from fixture metadata or a status snapshot.

A known acknowledgment is saved even when a later explicit read fails. No save triggers an automatic read or write replay. All edits lock until an explicit current-state read and acknowledgment; uncertain saves retain their draft. Independent drafts survive paging and reads, and remain inspectable if a video becomes ineligible. Native link/beforeunload guards cover edited drafts; pagehide aborts requests and BFCache restoration requires explicit review. Global programmatic/history/multi-tab identity transitions remain open. Client account checks do not certify backend revocation/eligibility races.
