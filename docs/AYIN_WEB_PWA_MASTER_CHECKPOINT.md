## Accepted Phase4E — duplicate-safe TV focus identity

**Start:** accepted/deployed main `1b864a3949fe10fa99aa58b80e130db26bd35e5b`. **Branch/PR:** `web-pwa-phase-4e-tv-focus-identity`, #149. **Final reviewed PR head:** `8f413ba010d87d2c0fa181ea05cd66105943ece9`. **Merged/deployed main:** `4da970c5fa1f2abbd53f100f69c49832f0fb3016`.

**Finding and change:** repeated semantic `data-tv-focus-id` values are legitimate when the same media appears in multiple rows, but the previous geometry adapter passed duplicate IDs directly to `findNextFocusTarget`, causing the first DOM occurrence to masquerade as the current target. `TvFocusScope` now derives occurrence-aware runtime identities while leaving semantic attributes untouched. Unique named targets keep stable persistence, duplicate targets persist occurrence-aware keys, legacy raw session values still resolve, and a saved duplicate occurrence falls back to the semantic target if later data leaves one copy. Focused dialogs remain isolated geometry scopes. No API, schema, permission, ownership, provider or native fork changed.

**Regression and database evidence:** pure tests cover duplicate uniqueness, legacy compatibility, duplicate-to-unique recovery and unnamed targets. Browser acceptance mutates two real Viewer navigation links to the same semantic focus ID in different rows and proves ArrowRight selects the lower aligned target. The phase also exposed a pre-existing Task86 EXPLAIN assumption: PostgreSQL validly reordered the discovery semi-join and used `Video_pkey`. The corrected regression separately proves `video_public_feed_idx` is selectable for the Video feed component while the full discovery path stays index-backed, free of Seq Scan and uses `media_asset_playable_video_idx`. Production SQL/indexes were not changed.
