# One verified account workspace

Account overview previously fetched unchecked identity independently of session, MFA, privacy and finance panels. A panel could manually verify account B while the overview/other panels retained A. The account route now bootstraps one bounded, projected identity using captured pre/protected/post account checks before mounting private children. A context binds their initial/protected reads and MFA commands to that root identity; standalone Studio finance retains its independent existing behavior.

Any child-confirmed scope/session loss closes the root. Actual pagehide/hidden visibility also closes it. The native whole-account wrapper is hidden before child secret/form cleanup, requests abort and operation generations invalidate. Controlled inputs can retain React defaultValue after form.reset(), so native values/defaults are explicitly cleared too. MFA QR sources/manual keys/recovery-code DOM text are cleared before unmount. This is bounded UI/history privacy behavior, not a claim of JavaScript heap wiping or operating-system memory erasure. No persisted-pageshow/focus reread or mutation replay reopens a closed root. One public EN/AR Read current account action resolves a fresh identity and remounts empty private inputs; private panels cannot reopen independently under another identity.

Overview renders only the verified projected context, without its old independent unchecked request. Identity parsing bounds text/UUIDs and safe path handles/slugs; unknown password/private fields are not projected. MFA status and secret-producing commands have protected pre/post account checks. A rejected MFA factor is distinguished from invalid session/account authority: setup is retained only after another actual protected current-account status read, without replaying its command. Unconfirmed/acknowledged-but-unverifiable MFA writes close the workspace; intentional validated disable still redirects to sign-in without pretending a subsequent logged-out actor read can succeed. A separate failed settings read can retain already known one-time codes only after another scoped current-identity check.
