# Direct advertiser and campaign workspace candidate

## Inspected baseline and finite scope

The source baseline is `128f6a96cdcd835dc5388b0ccf5f8e3b562717fd`, tree `2b419fa82c5f7d47ae238c37da4fa4c792a6da57`. It preserves the accepted Advertising navigation, caption-compatible Studio pagination and public/upload stack. This candidate replaces only the legacy AdvertiserManager/CampaignManager with a native searchable EN/AR workspace. Inventory, creative, seller, player and provider controls retain their existing implementations and are not certified by this work.

The actual advertiser/campaign APIs already provided create/update/delete, normalized direct configuration, role/step-up route guards and transactional audit insertion. Source inspection found prerequisite correctness gaps: guard-only authority, unversioned overwrites, schedule validation outside the transaction, unlocked deletion preconditions, and undifferentiated 400 errors. The legacy frontend cleared create drafts after rejected mutations and refreshed campaign drafts after reads. Existing capabilities were reused rather than replaced.

## Bounded protected-write prerequisite

Advertiser/campaign mutations now pass the validated actor through the existing `lockAdminAccountWrite` authority primitive. Ordered actor, advertiser and campaign locking protects current authority and deletion/schedule conditions. Existing `updatedAt` versions advance monotonically even when the clock is unchanged. Direct-config-only edits advance the owning campaign version. No schema migration or historical correction is involved.

Workspace commands include a fresh correlation ID and the reviewed version (including the advertiser version when creating a campaign). The data and audit record commit together; the response binds the exact actor, command, action, entity and version. The same actor can explicitly retrieve the committed audit acknowledgment after a response is lost. A missing audit record does not prove failure and never authorizes automatic replay. Legacy uncorrelated response shapes remain compatible, while all advertiser/campaign writes receive current transactional authority checks.

Workspace reads use a repeatable-read snapshot for advertiser/campaign/config consistency. Typed frontend parsing rejects malformed or contradictory responses. Explicit validation, access, missing-target and conflict responses remain distinct from uncertain transport/server results. A successful acknowledgment is not reclassified as a failed write because a later identity or refresh read fails.

## Bounded shared Admin identity prerequisite

Account ID and role equality could not distinguish logout/relogin to the same account. The existing Admin session response now includes non-authenticating durable session scope metadata, checked against current server state. An optional expected-session header binds native requests to that session, alongside the existing expected-account header; absent-header legacy callers retain their existing contract.

The existing AdminAccessProvider owns a memory-only shelf limited to this migrated workspace. Synchronous lease revocation conceals opted-in native fields before state cleanup. Hidden/pagehide/freeze, failed or malformed identity reads, off-Admin departure, provider unmount and changed account/role/session/version destroy private drafts, including while the editor is absent. A same-scope Admin route recheck may retain an inaccessible candidate, but returning to the workspace requires an explicit fresh record/version read. Delayed reads cannot revive old leases or draft data. No browser storage, credentials, grants, periodic polling, history rewriting or router framework is introduced. Legacy consumers that have not adopted this scope contract do not gain implied whole-Admin privacy certification.

## Native flow

- Two existing tabs retain their canonical Advertising location and use shared native fields, buttons, disclosures, badges, pagination and confirmation dialogs.
- Search/filter covers every returned advertiser/campaign record. The displayed pages are client-side slices of the existing full result, not a claim of database pagination.
- Campaign creation starts with a name and advertiser and defaults to DRAFT. Status, schedule, exact decimal pricing metadata, existing priority/frequency/pacing limits and targeting are optional disclosures. Selecting ACTIVE requires an explicit review confirmation.
- Untouched saved dates preserve their original instant and millisecond precision; untouched null currency/direct configuration and decimal strings are not rewritten by a name-only edit. Unknown saved placement keys and existing target IDs remain present.
- Searchable advertiser/channel/video selection uses the existing protected directories. Existing unknown target labels are shown honestly as IDs until an authoritative result supplies a label.
- Dirty and in-flight read edits retain their original version. A concurrent version must be explicitly reviewed before an intentional save against the newer baseline. Delete and dirty-close use the shared confirmation dialog. Lost outcomes lock writes until original-action review; no retry is automatic.
