# مراجعة AYIN الهندسية — 16 أكتوبر 2026

**P2 CONFIRMED_BUG — أدوات التشغيل والقبول:** ملف CSP كان موجودًا في archive، لكن smoke شغّل Next من جذر المستودع بدل `apps/web` التي يستخدمها PM2. صُحح cwd دون تغيير تشغيل الإنتاج أو تخفيف الترويسات؛ نفس archive الإنتاجي فشل قبل التصحيح ونجح بعده. وأُصلح سباقا انتظار الحالة في اختبارات الإعلانات وClips بعد مراجعة traces، دون زيادة مهلات أو محاولات. هذه عيوب أدوات قبول، وليست دليل تعطل الإنتاج.

**P2 CONFIRMED_BUG — Clips أثناء التحميل:** نص الحالة وسّع عمود الإجراءات على عرض360px فدفع رابط المشاهدة أسفل المساحة المرئية. إصلاح CSS من خمسة أسطر يحتوى القياس العرضي للنص. قبل الإصلاح في CI: أسفل الرابط735.56px مقابل مساحة713px؛ بعده في متصفح محلي مبني:662.97px وقابل للنقر. نجح اختبار واحد لحالات pending ثمHTTP500 ثم تمرير metadata للوصول إلىRetry ثمready؛ ظل تمرير الصفحة0 والتنقل ثابتًا. هذا قبول Chromium مع API ووسائط اصطناعية، لا هاتف فعلي.

**إثبات مالي إضافي على PostgreSQL:** في Run `38936475098`، مرشح الدمج `b019466a6a861c7312dfc85bd373766a639b2846` للرأس `6fc9b654ee5f892552d741cc755c4e5855338966`، فشلت ست حالات API فعلية: إنشاء عقد واستيراد وتعديل مالي بعد سحب الدور أو تعليق الحساب أعادت 201 بدل 403. هذه **P1 CONFIRMED_BUG**. المعاملات الثلاث تبدأ الآن بحجز صلاحية الحساب والدور قبل أقفال القناة أو الكتابة. الحالة السابعة أثبتت `deadlock detected` بين تغيير أدوار الموظف والتحقق المالي؛ **P2 CONFIRMED_BUG**، وعولج ترتيبها بقفل Account قبل حذف الأدوار في `admin-governance.service.ts`. فشل الاختبارات السبعة ليس فشل تهيئة: تثبيت/بناء/migrations/seed نجحت، والأربع حالات السابقة وثلاث حالات عقود قديمة نجحت. نجحت الحالات الأربع عشرة بعد الإصلاح: Run `38937883151` / job `117097845628` على مرشح الدمج `dc1b559ae14e778a955a4f58893e56153ec68826` من الرأس النهائي `719d6bbcc8b95547a336296dc4d88b8576ab56b1`: عشر حالات عقد/سلطة وأربع تسوية، بلا إخفاق أو deadlock. هذه سبع حالات انحدار جديدة نجحت بعد إثبات فشلها.

**تحسين قابل للاختبار:** `GET /media/uploads/policy` محمي بالمصادقة و`private, no-store` ويقرأ حجم الملف ومدة الجلسة من الإعدادات الفعلية. تعرضه QuickUpload قبل الاختيار؛ فشل الاستجابة أو عدم صلاحيتها يمنع البدء مع إعادة محاولة. اختبار Chromium أثبت 1024 بايت مقبولة و1025 مرفوضة قبل أي كتابة، ومعالجة 503 واستجابة غير صالحة. هذه أرقام fixture فقط؛ لم يتغير حد الإنتاج. لا وعد باستئناف Reload أو استمرار خلفية الهاتف في المسار العادي.

**التوافق والتراجع:** لا migrations أو خدمات جديدة في هذه الإصلاحات. الإصلاح المالي يسلسل استيرادات المصدر نفسه، وتحقق الرفع يضيف قراءات وأقفالًا للسلطة، والمحدد محدود الذاكرة والعمل. التراجع يتم بإعادة الكود بعد المراجعة؛ لا يُصلح تاريخًا ماليًا سابقًا ولا يبرر إزالة حماية مثبتة. أي تكرار مالي تاريخي يحتاج فحصًا قرائيًا ثم قيد تصحيح مدقق. لم تُعدّل بيانات إنتاج لتجميل النتائج.

بوابة الإصدار تربط Archive وprovenance بالـSHA والمستودع وworkflow وRun ID وAttempt وchecksum، وتمنع المصادر غير الموثوقة والنتائج المفقودة أو المتخطاة وSHA متقادمًا. مفاتيح SSH المثبتة وموافقات production والتحقق من الصحة والرجوع إلى الإصدار السابق باقية. artifacts القديمة لا تستوفي العقد الجديد تلقائيًا؛ الرجوع التشغيلي إلى release موجود مستقل عن إعادة نشر artifact قديم، ولا يعكس migrations.

## 7. ما بقي ولم يُصلح جانبيًا

- **P2 CONFIRMED_DESIGN_GAP:** جلسة الرفع التقليدية 900 ثانية افتراضيًا دون تجديد؛ الملف الكبير أو الاتصال البطيء قد ينتهي قبل الإتمام. الحل يحتاج عقد تجديد يعيد السلطة والحصة أو توسيع V2 بعد قبوله؛ لا قبول رمز منتهي بناءً على وجود object.
- **P2 CONFIRMED_DESIGN_GAP:** `cleanupAbandonedUploads` موجود بلا مستدعٍ غير اختباري عُثر عليه في المصدر. قد تبقى مصادر PENDING وحصة محجوزة؛ يجب التحقق من تشغيل خارجي قبل ادعاء تراكم إنتاجي، ثم توصيل تنظيف محكوم لا يمحو ديون UNKNOWN.
- **ALREADY_FIXED ضمن هذه الجولة:** إعداد تقليدي 50 GiB مع جزء 5 MiB كان ينتج 10,240 جزءًا ويرفضه العميل بعد تخصيص التخزين. الخدمة تختار الآن `max(configPartSize, ceil(size/10000))` وتعلن وتوقع القيمة نفسها؛ ست حالات حدود، اثنتان فشلتا قبل الإصلاح. حدود الملف والحصة وV2 لم تتغير.
- **P1 CONFIRMED_BUG، إصلاح قيد قبول المتابعة:** أثبت PostgreSQL سباق Complete/Abort التقليدي؛ الإلغاء قد يحذف مصدرًا قُبل للمعالجة. الإصلاح يسجل لقطة إلغاء V1 والتزامات التنظيف قبل I/O. لا ينقل ضمانات التسوية النهائية في V2 إلى المسار التقليدي، وتظل حصة الديون غير المحسومة محسوبة. انظر أدلة المتابعة أدناه.
- **P2 CONFIRMED_DESIGN_GAP:** CSP ما زالت تسمح inline للتمهيد؛ السياسة الأضيق Report-Only تجريبية. اختيار nonce/hashes يحتاج التحقق مع Next المثبت والتوليد الديناميكي والكاش وR2 وSDK؛ لا XSS مثبت من هذه السماحات وحدها.
- **NOT_REPRODUCED:** اختيار العقد بتاريخ periodEnd يطابق السياسة الموثقة في `docs/REVENUE_LEDGER.md`؛ لا تعديل تجاري مطلوب من هذه الملاحظة. مسارات المزود الخارجي المعطل تحتاج قبول sandbox قبل التفعيل. المتابعة أثبتت وأصلحت سحب السلطة في compliance والنزاعات، كما هو موثق أدناه.
- **CONFIRMED_DESIGN_GAP:** CSV المالي يجمع تاريخًا كاملًا في الذاكرة؛ لا قياس يثبت انهيارًا حاليًا. قِس حجم التاريخ ثم stream/paginate دون قطع البيان أو تغيير العملة.
- **BLOCKED_EXTERNAL:** إعدادات R2 وCORS الخاصة برفع المتصفح، وصول الحساب الاختباري، مزود الإعلانات/الموافقة، الأجهزة، حالة النسخ والاستعادة، موارد الخادم وعمق الطابور. لا اتصال دفع خارجي مفعّل في binding الحالي.

## 8. خطة تيست يمكن البدء بها

1. **قراءة عامة الآن:** الصفحة والبحث والقناة وWatch لمحتوى اختبار مملوك، دون حذف/تعديل بيانات حقيقية. المتوقع عرض حالات حقيقية لا نجاح وهمي؛ دوّن request ID والخطأ دون tokens.
2. **مرشح معزول:** تثبيت Node/pnpm المقيدين، PostgreSQL اختبار باسم ودور مخصصين، ثم guards والمigrations والجودة والوحدات والتكامل والبناء. الفشل أو SKIPPED يظل ظاهرًا؛ لا fallback للإنتاج.
3. **الحساب والماليات:** حسابان ومشرف اختبار، توفير تلقائي واحد، تبديل حساب/MFA، عقد 60% وتقارير USD/EUR وتصحيح وإعادة طلب وسحب دور متزامن. المتوقع تطابق البيان وAdmin/Creator وعدم تكرار قيد أو تحويل مال.

5. **قبول R2 محكوم:** الحساب والتفويض والنطاق الجديد، MP4/MOV/حاوية ثانية، المعالجة والنشر والمشاهدة وRange؛ تنظيف أشياء الاختبار وحدها. لا توسع V2 أو backfill لتجاوز عائق.
6. **الأجهزة والاستعادة:** iPhone وAndroid فعليان، PWA وتدوير/صوت/انقطاع، ثم استعادة نسخة مشفرة إلى قاعدة غير إنتاجية ومراجعة المراقبة والرجوع. بعدها فقط يُعاد بحث GO_LIMITED_BETA.
