# AYIN explicit Google age-treatment safety evidence

This phase11/14 slice closes an actual adapter defect: /ads/gam/config reported personalized mode when a restrictive child flag was set and omitted the child-directed signal from IMA parameters. The Web adapter also had no explicit age-treatment provider contract. Existing public content eligibility, disabled/unconfigured/test-mode/independent/emergency kill switches, exact seller identifiers, limited-loader safeguards and Kids Watch no-general-ad mount boundary remain preserved.

Official sources reviewed2026-10-03:

- Google Ad Manager [age treatment](https://support.google.com/admanager/answer/3671211?hl=en) now marks TFCD/TFUA deprecated and specifies TFAT child1/teen2/unspecified0. Child and teen treatment disable personalized ads/remarketing; child applies additional vendor/identifier restrictions. Legacy child flags therefore remain restrictive during migration.
- Google [GPT reference](https://developers.google.com/publisher-tag/reference#googletag.PrivacySettingsConfig) supports tagForAgeTreatment using googletag.enums.TagForAgeTreatment. The enum's runtime value is used directly; no undocumented numeric GPT value is invented. The reference also retains legacy fields. Clearing age treatment requires an explicit unspecified setting; AYIN never sends that clearing signal from an absent age classification.
- Google [IMA HTML5 consent guide](https://developers.google.com/interactive-media-ads/docs/sdks/html5/client-side/consent) still describes legacy TFUA, while the newer Ad Manager policy describes TFAT for video. AYIN retains positive legacy parameters and adds the current TFAT; it does not erase a restrictive tag during migration.
- Google [CMP requirement](https://support.google.com/admanager/answer/13554116?hl=en) remains a separate certification/platform requirement. A provider contract or restrictive flag is not evidence of a certified deployed CMP.

The public configuration accepts an explicit known ageTreatment (CHILD/TEEN/UNSPECIFIED) alongside existing legacy flags. CHILD dominates TEEN/unspecified whenever either explicit legacy child flag is true. Restricted personalized requests become NON_PERSONALIZED; LIMITED_ADS remains limited. Current IMA tfat1/2 is emitted with npa/ltd and positive legacy tfcd/tfua. Unknown/duplicate/malformed context returns400 instead of an uncaught Zod500. Responses are private/no-store. No age is inferred from device, channel, account or arbitrary user IDs, and targeting stays empty. This configuration endpoint does not itself deliver ads and the current browser consumers do not fetch it; it is not represented as an end-to-end trusted age policy.

The shared Web consent snapshot accepts only optional explicit CHILD/TEEN. A valid restrictive age signal survives otherwise-invalid consent as a limited fallback. Restricted personalized snapshots downgrade to nonpersonalized; malformed age snapshots fall back to limited without inventing classification. GPT uses the loaded SDK's actual enum, validates it before queuing any slot creation, and rejects restricted mounts when the SDK age API is unavailable. Absence of a classification never sends a clearing value. IMA retains all positive restrictions already in Google tags, gives CHILD precedence across duplicate TFAT and legacy child flags, adds npa for either restricted age, retains ltd and unrelated tag parameters, and leaves third-party URLs unchanged.

Two additional API units, four additional Web units, an actual AppModule/PostgreSQL suite with3 HTTP cases and two additional controlled IMA browser journeys cover migration/conflict/limited preservation, missing SDK API with0 slot/delivery calls, default/private headers,400 validation, no ad-event/audit writes, real database emergency kill switches, intact tag parameters and HLS content resumption. Existing legacy/privacy/playback cases remain intact; one existing IMA browser case now checks legacy CHILD takes precedence over conflicting TFAT TEEN. Unit mocks and isolated example publisher identifiers are controlled evidence, not Google delivery certification or production activation.

Local types/lint/format/unit results and own-head actual PG/security/inventory/browser results are recorded separately. Final own-head gates/review/merge/exact release remain pending. Trusted Kids/profile/account/consent policy across every decision/VAST/event path, real deployed CMP/TCF/region/legal classification, global consent transitions with mounted slots, actual provider delivery/native SDK/device acceptance, and all master phases0–16 remain open. No production ad account or provider has been activated by this change.
