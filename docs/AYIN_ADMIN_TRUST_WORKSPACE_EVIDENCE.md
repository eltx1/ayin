The existing English-only dense page and browser reason prompts become shared EN/AR workspaces for Queue, Decisions, Your actions and Settings. Native labeled decision/status/reason forms replace prompts. All four actual bounded queue categories, actor actions and nested case reports remain reachable; twenty-row presentation controls are explicitly not database pagination or lifetime archives. Unknown wire values are validated before display: session roles and account UUID, open/reviewing queue enums, dated unique bounded records, valid target references, appeal/action identity and actual nullable resolution/settings/flags. Diagnostic fields are omitted from the presentation. Empty/failed reads do not fabricate counts; queue data disappears while reading or after malformed/error responses. Programmatic/history/global multi-tab identity handling remains separate.

The role-authorized GET /admin/trust/records/:kind/:id supports cases, appeals, takedowns and channel trust only, validates enum/UUID before any Prisma access, and returns an actual current record including terminal states. It uses the same existing Auth/Admin guard/role/MFA policy as the queue and decisions. This closes a practical recovery gap: a committed CLOSED/UPHELD decision disappears from the open queue, but explicit review can now display its actual saved status/resolution/update time. A guarded404 is displayed as record absence, not proof that a previous write did not commit. GET snapshots/actor ledger/records/Creator history explicitly use Cache-Control:no-store. No new public read, arbitrary model accessor, permission relaxation, automatic decision or replay is introduced.

Before a manually requested mutation, the helper independently verifies the actual current actor and role scope within the same30s aggregate deadline, preventing a stale signed-in page from submitting under a changed account. The server remains authoritative for changing permissions/MFA/Origin/audit/enforcement. Verified acknowledgments reset only the appropriate draft; unknown write outcomes retain it and lock all decisions until explicit current-record review and confirmation. Preflight identity/authorization denial sends no POST and clears the old snapshot/drafts. A read failure cannot turn a verified saved operation into a failed write.
