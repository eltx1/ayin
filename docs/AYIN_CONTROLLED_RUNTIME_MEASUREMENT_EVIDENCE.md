Master Phase10 remains unfinished. This candidate adds repeatable observations to the existing real AppModule/PostgreSQL and production Next browser suite; it does not infer speed from entry bytes or claim field Core Web Vitals, production percentiles, a physical device, provider/player/upload performance or concurrency certification.

Two explicitly configured Chromium profiles use fresh contexts for each of three `/browse` and `/studio/analytics` samples: desktop1440×1000/CPU1/unthrottled; mobile390×844/CPU4 relative slowdown/150ms minimum request latency/200000 download and96000 upload bytes per second. Browser HTTP cache is disabled and Service Worker blocked. The existing isolated local `ayin_e2e` fixture seeds28 complete daily projections/280 views/27 threshold-visible audience/cohort/subscriber rows; data comes through actual existing API reads, not mocked metrics. The server is already warmed by the suite; this is not a cold-server or PWA-startup comparison. The current CDP replacement condition commands were actually probed and are absent from the pinned local Chromium. The supported compatibility command `Network.emulateNetworkConditions` applies the same explicit limits and is recorded in each report; its documented deprecation is retained, without a broad dependency upgrade or an unthrottled substitute. Any failure applying conditions fails the measurement.

Each JSON records source commit/tree, Node/Chromium, exact conditions, TTFB/DCL/FCP/observed LCP, session-window layout shift calculation excluding recent-input shifts, long tasks, renderer CPU counters/heap, DOM size and bounded category-level CDP encoded byte/request/error totals. Unavailable/reset CPU counters stay nullable. Analytics then receives actual trusted tab/paging clicks and raw duration-threshold Event Timing entries, explicitly not an aggregated INP score. No load-only interaction metric or field75th-percentile claim is made. API reads record12 actual7/28/90/365-day client roundtrips/body bytes and qualified row counts, separately unthrottled and not mislabelled as server query time.

A guarded read-only fixture helper runs actual PostgreSQL EXPLAIN ANALYZE/BUFFERS for three representative365-day owner-filtered aggregate/audience/subscriber-cohort query shapes. Only plan nodes/index names/cardinality/timing/block counters survive the allow-list; literal filters, identifiers and SQL response bodies are not persisted. This is a small seeded database plan baseline, not all emitted Prisma queries, production cardinality, index justification or connection pressure. No schema/index/pool/replica change follows without evidence.

The existing browser workflow preserves both JSON reports under `controlled-runtime-measurements`; actual reports, final-head workflow gates and interpretation remain pending until collected and reviewed. No measurement number is invented in this candidate document. Secrets, cookies, headers, browser storage state and account/profile/video IDs are not written to reports.
