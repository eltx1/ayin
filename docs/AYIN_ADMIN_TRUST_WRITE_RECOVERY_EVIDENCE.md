# Admin Trust write recovery candidate

Source review found that the page awaited a full queue refresh inside its write handler: a committed decision followed by failed GET was presented as a failed write, while response loss unlocked controls immediately. Two asynchronous form handlers also dereferenced event.currentTarget after the event had finished. This focused repair verifies protected acknowledgments against the actor, target, decision and submitted fields, captures the form before waiting, resets it only after a verified acknowledgment, and treats uncertain responses as locked outcomes with retained drafts. It does not automatically refresh or replay a write. A synchronous decision guard covers state-update gaps; all write buttons stay locked until an explicit read and review confirmation.

An existing-role-protected GET /admin/trust/actions exposes only the current authenticated actor's latest100 moderation actions, ordered by createdAt/id. The presentation validates actor ownership, distinct UUIDs, enums, dates, target references and the bound, and displays the full actual reason/targets/timestamp for explicit outcome review. This is a recent actor ledger, not a lifetime archive, idempotency token or proof that another equal-looking action was caused by this visit. The existing controller Auth/Admin guards and role scope remain; no MFA, reauthentication, Origin, audit or enforcement service policy is bypassed or weakened. No schema/index change is inferred from this small surface.

Reads first resolve the current role, issue no trust reads for unrelated staff, apply a combined15s deadline across the snapshot and recheck the same actual actor and role set before display. Transport responses are bounded15s for GET/30s for writes and canceled on caller abort; pending writes abort on pagehide/unmount. Failed reads hide the old queue, prevent acknowledgment and preserve draft settings; explicit authorization denial clears settings and identity. Missing queue observations display Unavailable rather than fabricated zero. Review refresh does not overwrite changed settings. Default prompts no longer claim an evidence review or an appeal decision that the operator has not written.

Four actual API/PostgreSQL browser journeys cover acknowledged action plus failed explicit refresh, committed response loss with retained reason/no autoread/no replay and actual actor-ledger review, no requests for finance-only identity, and actor-owned action reads denying another actor's records and unrelated staff. Seven unit cases validate wrong record/actor/target/status/settings, malformed acknowledgments and unsafe ledger rows. Local/full CI results and acceptance remain pending.

This is a focused Phase7/14 write-safety repair. The existing wider page still needs complete EN/AR shared-UI consolidation, native decision forms in place of prompts, queue/settings wire parsers, database paging/archival coverage, dirty-navigation handling and a global identity-transition pass. Existing queue limits and nested-report cardinality are not fixed or misrepresented as complete pagination. Full Admin/Creator, field performance, physical devices/providers and the master phases remain open.
