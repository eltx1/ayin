# Creator Trust & Safety consolidation candidate

The existing `/studio/trust` page silently ignored read failures and presented JSON diagnostics without a creator workflow. This Phase6 slice replaces it with one shared EN/AR route heading, actual channel trust, moderation actions, notice details and appeal history. Every row in the existing latest100 action/appeal/notice snapshots is reachable through twenty-row presentation pages and native disclosures. This is not database pagination or a complete lifetime archive. The current API's trust-state list is unbounded; the client rejects more than100 rows rather than silently truncating or claiming complete large-membership acceptance.

Allow-listed date/enum/count/UUID/duplicate validation strips actor identifiers and arbitrary notice JSON from presentation. The actual account is checked before and after a no-store history read; foreign appeal/notice account IDs and mismatched action correlation are rejected. Missing/error reads clear displayed history, retain the local appeal explanation while access remains valid and provide explicit retry. Reads are bounded15s; appeal requests30s. Server AuthGuard, channel membership/target ownership and rate limits remain authoritative; no role, publication, rights, Origin, moderation/finance or audit policy is changed.

The previously unreachable existing appeal endpoint now has a labeled owned action picker and20–5000-character explanation. The acknowledged reply must match the account, action, exact message and OPEN status. Synchronous guards prevent read/write overlap or repeated submissions, and a known acknowledged action stays blocked within the visit. A lost reply retains the explanation, does not trigger a read/write replay and requires explicit history review plus acknowledgment; an actual open appeal then keeps the same action blocked. Successful writes are distinguished from later reads and do not fabricate new history rows. Dirty native link/unload prompts, pagehide abort/uncertainty and BFCache recovery protect local work. History/programmatic navigation and full account-transition synchronization remain open.

Local canonical Web lint/types,380 unit cases (seven new meaningful contract/timeout/correlation cases), strict new E2E typecheck and default Turbopack build passed. Three actual PostgreSQL/browser cases remain pending: EN/AR26 owned actions/25 appeals/25 notices/all-row paging/native disclosures/metadata-free presentation and real appeal creation; committed appeal with deliberately lost acknowledgment/no-auto-read/no-replay/retained explanation/explicit review/503 recovery. The fixture is a separate guarded local ayin_e2e helper, seeded through actual schema models; it does not certify Admin moderation decisions, rights adjudication, successful appeals or production policy.

Full Creator/master phases0–16 remain open, including historical archives, video-only moderation targeting not exposed by the current history contract, denial/error semantics of the existing backend, large membership counts, global identity, Admin protected workflows and device/provider/security/advertising gates. Final-head CI, EN/AR390/1440 visual inspection and release evidence remain pending.
