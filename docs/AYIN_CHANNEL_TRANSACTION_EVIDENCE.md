# Channel transaction safety candidate

Actual source review found that concurrent channel handle edits read the previous handle before waiting for the row update, and competing image completions read the previous selected image outside their transaction. A late channel removal, owner revocation or asset completion could therefore invalidate the earlier read; obsolete image selection and cleanup could leave an uploaded orphan or preserve the wrong previous-handle history.

This focused API slice serializes owner/admin channel metadata and asset authorization/completion on the existing Channel row. It rechecks current channel status/removedAt and existing owner or scoped admin authority inside the transaction, after the lock. Handle changes then use the actual committed prior handle. Image completion retains existing stored-object size/MIME validation, locks the actual MediaAsset row, rechecks its pending/owned/unchanged metadata, reads the current channel appearance and commits upload state, selected pointer and superseded-asset removal together. Storage cleanup starts only after a successful commit and targets the actual superseded asset. No schema, publication, rights, Origin, MFA/reauthentication, provider or finance permission changes.

Six new real PostgreSQL integration cases use independent transactions and observed pg_stat_activity lock waits, not sleeps: prior-handle preservation, concurrent removal rejection, competing image completions/cleanup of the loser only, late pointer-write failure rollback/no cleanup, owner revocation after lock wait, and duplicate concurrent completion (one success, one rejected). They remain pending until CI executes them; no PostgreSQL service is available locally. Local392 existing API unit cases, lint and TypeScript pass after restoring the workspace's generated dependency outputs. Early local type/unit attempts lacked package-specific dependency links and config build output; corrected local results do not substitute for the database tests.

This does not close full master Phase6/14, all ownership-transition races, global lock order/load contention, production storage cleanup retries or native/provider/device acceptance. Existing Admin control writes naturally contend on the Channel update row; no independent staff role, audit or finance workflow is rewritten in this slice.
