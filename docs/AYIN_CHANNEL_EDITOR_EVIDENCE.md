# Channel editor consolidation candidate

This Phase6 slice covers the existing shared standalone `/channel/edit` and embedded `/studio/channel` editor with their Arabic routes. Full master phases0–16 remain open.

The previous client cast auth/channel/upload responses, allowed reentrant saves before React rendered busy state, issued immediate uploads from file selection, had unbounded requests and unlocked after lost mutation acknowledgments. It showed missing publishing settings as enabled/public defaults and provided English-only controls with visually hidden file inputs.

The new editor uses the actual account-selected channel, bounded15s no-store reads/30s API writes/120s credential-free image PUT, synchronous mutation/read guards, allow-listed channel/settings/assets and exact same-owner image paths. Image MIME/size checks precede authorization (JPG/PNG/WebP, avatar5MB/banner10MB); signed upload URLs stay ephemeral and are never rendered/logged/stored. Malformed/foreign-channel responses cannot overwrite the current channel. Existing public-channel helpers remain; obsolete unused unchecked editor transports are removed.

Shared EN/AR controls provide one main/h1 per route, labeled native file inputs, explicit image selection/upload, keyboard focus, truthful missing-settings state and all four actual publishing defaults. Recovery reads display the saved server identity separately from the retained local draft. A lost/error/malformed write response locks further writes, does not read or write automatically, retains a known authorized asset ID in memory and requires an explicit read plus acknowledgment before the next decision. A successful image acknowledgment must correlate to the authorized asset. Dirty native link navigation and unload prompt before abandoning drafts; browser-history/programmatic navigation and global account transition synchronization remain open. Pagehide aborts pending writes and marks uncertainty; BFCache restoration re-reads without replay. Auth denial clears owned display/draft/image data. No file, signed URL, draft or auth state is persisted.

Local canonical Web ESLint, strict TypeScript,383 Web unit cases (including ten new editor cases), strict new browser-test typecheck and default Turbopack production build passed. Two pre-existing Edge instrumentation warnings remain. Actual PostgreSQL/browser CI, EN/AR390/1440 final-head visual inspection and production release proof are pending.

Four new browser cases exercise actual registered-owner metadata PATCH/old-handle redirect in EN/AR, standalone/embedded landmarks and native file focus, rejection before image authorization, a real committed PATCH with deliberately lost reply/no-auto-read/no-replay/retained draft/explicit review/dirty-link cancellation, and actual owned authorization/PUT/real completion rejection/recovery. The isolated storage adapter returns video/mp4 object metadata for generic objects, so the image journey deliberately tests a partial upload rejected by the real completion API. It is not a successful R2/provider/storage certification. Unit tests cover successful correlated PUT/completion and credential-free/bounded PUT. Actual storage success, backend concurrent completion/removal/handle races, provider cleanup, history navigation and full identity transitions still need separate acceptance.
