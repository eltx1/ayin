# AYIN Comments security evidence

## Comments server availability safety candidate

Actual API review found that public comment reads/new writes and likes/reports checked only video/comment publication; they did not enforce the existing VideoPolicy rights/territory/override boundary or removed/suspended channel state. Profile resolution also omitted isKids, so direct requests could bypass the Kids UI's no-comments boundary. This focused backend correction reuses VideoPolicyModule and TrustedRegionService, requires available active-channel videos for public comment access and interactions, and rejects Kids-profile create/like/report requests before persistence. Public-list versus known-unlisted-write behavior is preserved. Existing account/profile ownership, Origin, rate limits, moderation/audit, owner edit/remove cleanup and server error shaping remain in place.

Local API lint/types and 386 API unit tests passed, including meaningful no-read/no-write assertions for removed/private/draft videos, inactive/removed channels, denied policy with country context, existing unlisted semantics and Kids writes. PostgreSQL/AppModule integration additionally checks that a spoofed country without the edge token cannot read a territory-restricted thread, a trusted region can read/create, expired rights block reads/create/like/report without persisted mutations, removed channels remain denied and Kids writes are blocked while owner cleanup works. Database integration/full browser/exact-head security/quality acceptance remains pending; local unit mocks are not database proof. No schema/provider/global auth change or full Phase14 certification is claimed.

Further source review found that the existing shared moderator check accepted every staff assignment without Admin role or MFA/session verification. Administrative comment actions now accept only existing moderation/operations/privileged roles, verify privileged MFA through MfaService and require recent session reauthentication for cross-channel administrative writes. Creator channel OWNER/ADMIN membership and own-comment edit/remove cleanup retain ordinary authority. New unit coverage exercises advertising-role rejection, scoped-staff freshness and privileged MFA account/version delegation. Real AppModule integration tests advertising/insufficiently verified scoped/privileged accounts across settings/moderation/heart/hide and asserts no changed records, with positive owner cleanup. Local389 API units/lint/types passed; final expanded exact-head database/browser acceptance remains pending.
