# AYIN current account-write authority and version evidence

Actual account patch and session revocation transactions previously relied on pre-handler authorization and accepted writes without a target version. A queued request could outlive its actor role/session or overwrite a newer account decision. This focused slice retains private cache headers, existing Operations/ADMIN/SUPERADMIN, Origin/MFA/step-up and atomic audit boundaries.

Both operations receive the actual authenticated request context. Their shared transaction locks the existing staff/MFA advisory identity, then actor credential before deterministically sorted actor/target Account rows with NO KEY UPDATE, then matched current role and session rows through commit. Credential-first order matches existing recovery-code regeneration; key-preserving Account locks avoid unnecessary foreign-key read blocking. Existing staff-role/reset/disable changes coordinate through the same advisory lock. Current ACTIVE actor/authVersion, exact unrevoked/unexpired session, actual role and privileged enabled MFA/version are rechecked after waits; five-minute step-up age is checked again. Missing targets return404. No cached pre-handler role grants authority to these transactions.

An optional strict timestamp contract preserves older callers; native account name/status/session commands always send their verified original account updatedAt. Inside the locked transaction, a mismatching target returns409 without account/session/audit side effects. Every accepted operation advances updatedAt monotonically by at least1ms, including session revocation; the smaller actual session acknowledgment remains unchanged without inventing status/date fields. CLOSED status decisions reject409 while explicit session cleanup remains allowed. Audit failure rolls back target/authVersion/session/version together. No automatic retry/replay or post-save private reread is added.

Twenty new actual AppModule/PostgreSQL cases are prepared: both status/session operations reject observed role, actor status/authVersion, actual session, MFA version, target and expired step-up winners after actual pg_stat_activity lock observation; a future timestamp advances monotonically and stale status/session requests cannot add audits; CLOSED/malformed versions; both actual audit-trigger failures roll back then explicit retries commit once; queued same-version access decisions produce one commit/one409; reciprocal actual name edits avoid cross-account deadlock without changing sessions. MFA winner tests deliberately block the actor credential, matching credential-first order. A new actual-browser case verifies real concurrent target change,409/original draft retained, direct target review plus explicit acknowledgment with zero replay/no audit. Existing EN/AR actual suspension/reactivation/session invalidation and complete browser/PWA suites remain.
