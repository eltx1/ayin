# Sitemap policy, pagination and current XML

Prepared source; own PostgreSQL and browser gates are pending. The complete route/SEO/master matrix remains open.

Actual current-main source was inspected and matched before editing. Counts used publication-only criteria and ignored distribution policy. Video feeds paginated before filtering policy. Playlist feeds selected only the first publication-eligible lead, then dropped the entire playlist when that lead was unavailable even if later items were available. XML also independently cached policy-dependent feeds for900 seconds and advertised stale public XML for an additional3600 seconds. A parseInt shard route accepted noncanonical aliases such as0junk.xml.

Counts and pages now use the existing authoritative publicVideoEligibility predicate before selection, with one captured actual clock per request. Playlist inclusion and lead selection both require actual eligible videos; a blocked first item cannot hide a later eligible one. Each count/page query projects its facts from one PostgreSQL statement snapshot. Video, channel and playlist images use bounded deterministic lateral selection instead of loading every related asset. Safe successful response shapes are preserved. Sitemap feeds remain global discovery with unknown territory, so region-restricted content cannot be added by spoofed client country headers. Channels remain discoverable when their own metadata is active, including valid empty channels.

Policy-dependent XML/count/feed reads now use no-store and bounded15-second fetch deadlines. Only explicit static public-route XML retains public caching. Shard names require canonical safe integers and API-supported offsets. Index assembly fails closed above50000 references as an implementation resource limit; hierarchical large-index design remains open.

Seven local helper cases include existing XML/shard cases plus canonical filenames, validated actual counts/no internal projection, no-store bounded reads/unsupported offset rejection and static-only caching. Five prepared real PostgreSQL cases verify50 unavailable rows before actual eligible pages, consistent counts, a blocked lead followed by eligible playlist content, force-allow hard-boundary rejection, safe deterministic images, no session/audit effects, malformed filters and policy changes after warmed reads. Two prepared real browser HTTP cases warm actual index/video/playlist XML then withdraw real rights and require fresh omission/404 immediately; aliases are rejected. Physical crawlers, CDN legacy-cache purging and a complete movie/series eligibility audit are not certified by this slice.
